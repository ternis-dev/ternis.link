# ternis.link — Bulk Operations Plan

> Date: 2026-10-01
> Status: DRAFT — for review before implementation
> Scope: CSV import + bulk edit/deactivate/delete + filtered export

## 1. Mission

Power users manage hundreds of links. Today it's one-by-one in Livewire/API plus a single unfiltered `GET /links/export`. Add symmetric bulk import + bulk mutate with per-row accountability, without letting one upload DoS the queue.

## 2. Goals / Non-Goals

Goals:
- CSV import (≤1000 rows/file, ≤512KB): `destination_url,domain_hostname,slug,expires_at,description,tags` — dry-run validation + async import.
- Bulk mutate on explicit ID lists (≤200 IDs/req): `tags add/remove`, `expires_at`, `is_active`, `domain_id` (move), `deactivate`, `destroy` (deactivate, never hard-delete — analytics preserved per tombstone policy).
- Filtered export keeps working; add `POST /v1/links/export` with same filters as `GET /v1/links`.
- Every bulk op is one `ActivityLog` row with per-row results downloadable for 7 days.

Non-goals (v1):
- No XLSX, no URL-fetch import, no scheduled/recurring bulk jobs.
- No cross-user bulk (admins keep existing `scope=all` list but bulk still owner-scoped unless admin).

## 3. Schema / Storage

- No new columns on `links`. New table `bulk_operations` (ULID):
  `id, user_id FK, type enum(import,update,deactivate,destroy,export)`, `status enum(pending,processing,done,partial,failed)`, `total int, succeeded int, failed int`, `input_filename varchar nullable`, `result_path varchar nullable` (disk `local`, 7-day TTL via scheduler prune), `error_summary json nullable`, `created_at`.
- Relation `User::bulkOperations()`.

## 4. API Surface (`links.t-api.de/v1`)

- `POST /v1/links/import` (multipart `file` CSV or JSON `{rows[]}`): validates synchronously (header check, row count, file size); enqueues `BulkImportLinks`; returns `202 {bulk_operation_id, status, total}`.
- `POST /v1/links/bulk` JSON: `{ids[≤200], action: update|deactivate|destroy, patch?: {tags_add[], tags_remove[], expires_at, is_active, domain_id}}` → `202` with op id. Ownership checked per row (non-owners reported as row errors, not 403 whole-batch).
- `GET /v1/bulk-operations`, `GET /v1/bulk-operations/{id}` (status + counts + `result_url` when done).
- `POST /v1/links/export` with `{tag, api_key_id, search, ids[]}` → streams CSV synchronously if ≤5000 rows else 202 + bulk op.
- Throttle: `throttle:api` + one running import per user (409 if already `pending/processing`).
- OpenAPI + `docs/api.md` with CSV sample.

## 5. Jobs / Services

- `BulkImportLinks` (ShouldQueue, `tries=1`, `backoff` n/a): streams CSV with `SplFileObject`, per row calls `LinkService::create` with row actor + domain resolved by hostname (must be owned/verifiable or active system domain); collects `{row, slug|error}`; writes result CSV to `storage/app/bulk/{op_id}.csv`; updates op counts; fires notification.
- `BulkMutateLinks`: chunks IDs 100, per link authorize + `LinkService::update/deactivate`; per-row errors captured (slug taken, domain unverified, quota) — never aborts batch.
- Limits enforced before dispatch: row count, file size, ID count, daily quota projected (`ensureWithinDailyQuota` + remaining).
- Cache: reuse `Link::forgetCachedSlug` per touched link (already in service); bulk path adds `Cache::flush` avoidance — one forget per link, queued.

## 6. Dashboard / Livewire

- Links table (`LinkTable.php`): checkbox column + toolbar (count, Select all-filtered ≤200, Tag, Expire, Activate/Deactivate, Move domain, Delete, Export). Confirm modal shows blast radius; runs via API-equivalent service call so web and API share logic.
- Import page (`dashboard.links.import`): dropzone, column map preview (first 5 rows), dry-run table with inline errors, "Import N valid" button, progress poll (Livewire poll on op status), result download link.
- `resources/views/dashboard/links/import.blade.php` + `App\Livewire\LinkBulkToolbar`, `LinkImport` components.

## 7. CSV Contract

```csv
destination_url,domain_hostname,slug,expires_at,description,tags
https://example.com/a,href.nz,launch-a,2027-01-01,Launch page,launch;marketing
```
- `tags` semicolon-separated (commas collide with CSV); normalized by `LinkService::normalizeTags`.
- `expires_at` ISO-8601, must be `after:now`; empty = none.
- `slug` optional; custom-slug plan minimum applies; empty = auto.
- Encoding UTF-8, LF/CRLF accepted; header required, unknown columns rejected.

## 8. Security / Abuse

- File: mime `text/csv|text/plain`, 512KB cap, 1000-row cap, formula-injection guard (cells starting `=,+,-,@` prefixed with `'` on export).
- Destination rows through junk + unsafe validators (same as single create).
- Result files on `local` disk, signed URLs (`Storage::temporaryUrl` or hashed route), owner-only + admin, auto-pruned after 7 days (`schedule: daily bulk:prune-results`).
- Notifications: completion writes to existing notifications inbox (no new mail).

## 9. Tests

- `BulkImportTest`: happy path, per-row errors (bad URL, taken slug, unverified domain), caps (1001 rows → 422), quota respected, guest 401.
- `BulkMutateTest`: partial success (one foreign id → row error, rest done), 200-id cap, destroy preserves `LinkTombstone`/analytics.
- `BulkExportTest`: filter parity with index, formula-injection escaping.
- `LinkTableBulkTest` (Livewire): select + toolbar + confirm + op polling.

## 10. Milestones

- M1: `bulk_operations` migration/model + routes + validation + OpenAPI skeleton.
- M2: jobs + result files + prune command + API tests.
- M3: Livewire toolbar + import page + docs (`docs/links.md`, `docs/api.md`) + full suite.

## 11. Risks

- Large imports exhausting daily quota mid-batch → pre-check `remaining = quota - todayCount`, import min(remaining, rows), rest marked `quota-exceeded`.
- Double-submit → idempotency key header (`Idempotency-Key` stored 24h) for `POST /v1/links/bulk|import`.
