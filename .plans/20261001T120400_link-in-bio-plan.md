# ternis.link — Link-in-Bio Pages Plan

> Date: 2026-10-01
> Status: DRAFT — for review before implementation
> Scope: bio page + sub-pages builder with per-button analytics, custom domains only (v1)

## 1. Mission

Linktree-style pages without leaving ternis.link: one custom domain = one bio page at `/` plus optional sub-pages, built in the dashboard, every button tracked. Reuses auth, domains, URL safety, OG, and click pipelines — no new hosting model.

## 2. Goals / Non-Goals

Goals:
- Builder on `dash.ternis.link`: pages, sub-pages (depth ≤1), button blocks (link, text/header, divider, social-icon), drag-sort, schedule windows, theme preset.
- Public render fast (<100ms p95, cached), mobile-first, light/dark, no JS required for clicks.
- Analytics per page + per sub-page + per button: views, taps, CTR, referrers/countries, per-day; CSV export.
- Abuse-safe by default: same junk/unsafe validators, Turnstile-gated creation, takedown via existing `is_removed` flow.

Non-goals (v1):
- No paid themes, no custom CSS/JS embeds, no forms/newsletter blocks, no e-commerce/price blocks.
- No system-domain hosting (`href.nz/b/handle`) — custom domains only (see §4 for why + alternatives).
- No multi-language variant routing (one locale per page, free-text only).

## 3. Hosting Decision (custom-domains-only v1)

Rule: a verified user domain (`user_id != null`, `isUsableForLinks()`) may be switched to `bio_mode`. When on:
- `GET /` renders the domain's root bio page (instead of landing/404).
- `GET /{sub}` renders a sub-page when `bio_pages.slug = {sub}` exists; otherwise falls through to existing short-link `RedirectController::resolve` (slugs keep working — sub-page slugs are reserved against link slugs on that domain, first-write-wins with 422 on collision).
- All other short-link routes (`/url/*`, `/go/*`, `/preview/*`, `/qr/*`) unchanged.

Why not system domains in v1:
- `/{input}` catch-all on `href.nz` already resolves slugs vs direct URLs (`SlugResolverService`); a `/b/{handle}` namespace would brand-mix guests with members and burn short namespace.
- Path collisions + phishing lookalike handles (`/b/ternis-bank`) are a moderation burden we don't need pre-launch.

Other ways (recorded, not v1):
- **A. `{handle}.ternis.link` subdomains** — cheapest later step; `canClaimSubdomain()` already gates family/partner/admin, wildcard roots already in `config/domains.php`. Good for inner-circle beta.
- **B. `ternis.link/b/{handle}` path** — single moderation surface, but pollutes the family domain and complicates `/{input}` routing; revisit only with handle allowlist.
- **C. Any-domain opt-in** (incl. system) — requires per-domain `bio_mode` + handle registry; do after abuse tooling exists.

## 4. Schema

`bio_pages` (ULID):
- `id, user_id FK, domain_id FK unique(nullable→one root per domain), parent_id FK nullable self (null=root, set=sub-page), slug varchar(64) (root: unused/`-`; sub: `[a-z0-9-]{1,64}` unique per parent), title varchar(80), bio varchar(280) nullable, avatar_url varchar(2048) nullable (https only), theme varchar(16) default `minimal` (`minimal|dark|paper`), accent varchar(7) nullable (`#rrggbb`), og_* reuse (title/description/image nullable, same caps as links), is_active bool default true, is_removed bool default false, published_at nullable, sort_order tiny, view_count bigint default 0, timestamps. Indexes: `(domain_id)`, `(parent_id, slug)`, `(user_id)`.

`bio_buttons` (ULID):
- `id, bio_page_id FK cascade, label varchar(60), sublabel varchar(120) nullable, kind enum(link,header,divider,social) default link, destination_url varchar(2048) nullable (required for link/social), icon varchar(32) nullable (allowlist: instagram,tiktok,x,youtube,github,globe,mail,…), thumbnail_url varchar(2048) nullable (https), sort_order tiny default 0, is_active bool default true, starts_at/ends_at nullable (schedule window), tap_count bigint default 0, timestamps. Index `(bio_page_id, sort_order)`.

`bio_events` (ULID, immutable, no updated_at):
- `id, bio_page_id FK cascade, bio_button_id FK nullable cascade (null=page view), kind enum(view,tap), referrer varchar(2048) nullable, user_agent varchar(512) nullable, ip_hash char(64) nullable, country_code char(2) nullable, city varchar(255) nullable, created_at useCurrent. Indexes: `(bio_page_id, created_at)`, `(bio_button_id, created_at)`, `(created_at)`.
- Deliberately separate from `clicks` (keeps redirect hot path + partitioning story untouched; no `link_id` join leaks).

Relations: `User::bioPages()`, `Domain::bioPages()` (one root enforced in service), `BioPage::buttons()/children()/parent()/events()`, `BioButton::events()`.

## 5. Public Rendering

- `BioPageController::showRoot/showSub` on `ensure.domain:partner` (custom user domains; system domains 404 here in v1). Order: root → sub-page → fall through to slug redirect (never 404 when a slug exists).
- Cache: `bio:{domain_id}:root` + `bio:{page_id}` 300s (same TTL as `LinkService::RESOLVE_CACHE_TTL`); invalidated on builder saves + deactivate; misses never cached.
- View counting: queued `RecordBioEvent(view)` via `BioTrackerService` (mirrors `ClickTrackerService` + `IpHash` + `GeoIpService`); bots (`CrawlerDetector`) get OG stub, no view counted.
- Button taps: `GET /t/{button}` 302 via `BioPageController::tap` (signed? no — public like redirects), counts tap + redirects; thumbnails proxied? No — hotlink only, `loading=lazy`.
- OG: root/sub-page `<meta og:*>` from page `og_*` → title/bio fallback (reuse `SocialPreviewValidator` caps; image via `UnsafeUrlValidator` https-only).

## 6. Builder (dashboard)

- New section `dash.ternis.link/bio` (`DashboardController::bio*` + `App\Livewire\Bio\PageBuilder`): domain picker (only owned verified domains without slug collision), root editor (title/bio/avatar/theme/accent/OG), sub-page list (`+ New sub-page`, slug field with live collision check vs `links.slug` on that domain), button repeater per page (kind switch, icon picker, schedule datetimes, pause toggle, drag-sort via `sort_order`).
- Validation mirrors API (see §7); avatar/thumbnail URLs get HEAD probe warning (reuse `SocialPreviewValidator::probeImage`), never block save.
- Danger: deactivate page/button (keeps analytics), no hard delete in v1 (tombstone story later).

## 7. API Surface (`links.t-api.de/v1`)

- `GET/POST /v1/bio-pages`, `GET/PUT/DELETE /v1/bio-pages/{page}` (DELETE=deactivate; `parent_id,slug,title,bio,avatar_url,theme,accent,og_*,is_active,published_at`).
- `GET/POST /v1/bio-pages/{page}/buttons`, `PUT/DELETE /v1/bio-buttons/{button}` (full replace via `sort_order` array optional `PUT …/buttons/reorder`).
- `GET /v1/bio-pages/{page}/stats?days=7|30|90&subpage_id=` → `{views, taps, ctr, by_button[{id,label,taps,share}], by_day[{date,views,taps}], top_referrers, top_countries}` (same shape as click summary, sourced from `bio_events`).
- `GET /v1/bio-pages/{page}/events/export` CSV (button taps, no raw IPs).
- Auth/ownership: owner or admin (`scope` like links); guests 401; plan gate: custom-domain plans only (reuse `allowsCustomSubdomain()`); per-user cap: 5 pages (root+subs count as pages? No — 3 roots, 10 subs each; buttons 25/page).
- OpenAPI + `docs/api.md#bio` + `docs/links.md` section.

## 8. Analytics Detail

- `views` = root/sub renders (human only); `taps` = button 302s; `CTR` = taps/views per page (buttons: taps/page-views).
- Dashboards reuse Chart.js patterns (clicks-over-time bars, doughnut shares); per-button table with sort by taps/CTR + CSV.
- Retention: `bio_events` pruned like clicks (follow existing cleanup job pattern); aggregates survive deactivation.

## 9. Security / Abuse

- Every `destination_url/avatar_url/thumbnail_url` through `JunkUrlDetector` + `UnsafeUrlValidator` (admin bypass: none for bio — even admins get checked, images are hotlinked).
- `slug` charset `[a-z0-9-]{1,64}`, reserved list (`url,go,preview,qr,bio,t,new,login,auth,api,v1…`) + collision check vs `links.slug` per domain (422 both directions; link creation later checks `bio_pages.slug` too).
- Creation throttled (`throttle:api` + `throttle:10,1` on public tap), Turnstile on builder create in v1? Builder is authed → skip Turnstile, rely on SSO + rate limits.
- Output escaped (`{{ }}`), URLs `rel=noopener`, avatars `referrerpolicy=no-referrer`; no raw HTML blocks in v1 (kills stored-XSS class).
- Takedown: `is_removed` hides page + buttons, keeps `bio_events`; admin list reuses link-moderation UI pattern.

## 10. Tests

- `BioRoutingTest`: root renders on bio-mode domain, sub-page renders, unknown sub falls through to slug redirect, system domain 404s for bio routes, reserved slug rejected.
- `BioBuilderTest` (API + Livewire): caps (4th root → 422, 26th button → 422), slug collision vs link slug both ways, schedule window hides button, deactivate keeps events.
- `BioAnalyticsTest`: view counted once per human render (crawler skipped), tap increments button + page CTR math, `by_button` shares sum 100%, CSV excludes IPs.
- `BioCacheTest`: edit invalidates `bio:*` keys; hot render hits cache (assert no DB query via `DB::getQueryLog` or query count).

## 11. Milestones

- M1: migrations/models (`bio_pages/buttons/events`) + `BioTrackerService` + public `showRoot/showSub/tap` + routing + cache + tests.
- M2: CRUD API + validation + stats/export + OpenAPI/docs + API tests.
- M3: Livewire `PageBuilder` + dashboard pages + OG/theme polish + full suite (`php artisan test`) green.

## 12. Risks

- Slug vs sub-page collision confusion → first-write-wins + explicit 422 message naming the holder ("slug taken by a short link" / vice versa); builder shows both namespaces side-by-side.
- Custom-domain-only limits adoption → mitigated by option A (`{handle}.ternis.link`) as the planned next step, no schema change needed (`domain_id` already generic).
- Event-table growth → same indexing/partitioning story as `clicks`; prune job from day one.
